# Бурёнка от SOLOMONA

Корпоративная B2B-платформа ShumDev: каталог фермерской продукции, торговые точки,
акции, заявки на сотрудничество, CMS и отдельное PWA собственника.

Стек: Node.js 24, Express 5 (ESM), EJS с расширением `.html`, SCSS, Vanilla JS,
Prisma 6.19.3, SQLite. React/Vue и публичного PWA нет.

## Быстрый запуск: Windows, CMD

Нужен Node.js **24.13.1 или новее в ветке 24.x** (проверено на 24.22.1).
Это полный проект. Распакуйте его в отдельную папку, сохранив прежнюю копию.
Не накладывайте весь архив на старую папку без резервной копии: старые удалённые
файлы ZIP автоматически не убирает. `.git` в архиве отсутствует.

После распаковки в `C:\Users\ШУМ\WORKS\burenka-ot-solomona`:

```bat
cd /d C:\Users\ШУМ\WORKS\burenka-ot-solomona
node -v
npm ci
if not exist .env copy .env.example .env
npm run env:init
npm run db:init
npx prisma validate
npx prisma generate
npx prisma migrate deploy
npx prisma migrate status
npm run seed
npm run user:create
npm run build
npm test
npm run dev
```

Сайт: http://localhost:3000
Админка: http://localhost:3000/admin

Скрипт `env:init` создаёт собственный SESSION_SECRET без вывода его значения.
`db:init` создаёт SQLite при первом запуске, не удаляя данные. Он нужен перед
первой миграцией. `seed` добавляет демонстрационные записи и не перезаписывает
существующие; не используйте его как импорт реального каталога.
`user:create` интерактивно спрашивает имя, логин, пароль и повтор пароля.
Готового логина/пароля и публичной регистрации нет. Пароль — от 12 символов,
ввод скрыт. Уже созданного собственника скрипт не заменяет.

При последующих запусках достаточно `npm run dev`. Для обычного запуска без
наблюдения за файлами — `npm start`. После изменения SCSS/JS — `npm run build`.
При изменении зависимостей — `npm ci`; при новых миграциях — `npx prisma migrate deploy`.

## Что уже работает

- SSR и URL без `.html`: главная, каталог и категории, товар, акции, партнёры,
  список и страница точки, о компании, контакты, поиск, документы, 404.
- Единая база продукции, поиск с кириллицей, регистром и ё/е; фильтры, сортировка,
  страницы результатов; черновики и скрытые категории исключены из публикации.
- Галерея товара, необязательные характеристики, рекомендации, переключение цены.
- Все разделы OWNER: обзор, товары, категории, производители, точки, акции,
  заявки, основной контент страниц, настройки и документы.
- Фото JPG/PNG/WebP: проверка реального содержимого, перекодирование, удаление
  метаданных, обложка, порядок, подписи. До 20 фото на запись, 8 МБ на файл.
- Заявки со статусами «Новая / В работе / Закрыта», заметкой, согласием,
  серверной валидацией, honeypot и ограничением частоты.
- Карта Leaflet/OSM без ключа, внешние маршруты, сортировка точек по прямому
  расстоянию; координаты посетителей не отправляются в backend.
- OWNER-сессии в SQLite, scrypt, CSRF, HttpOnly/SameSite cookies, rate limiting,
  XSS-экранирование, CSP, закрытая статика и безопасная загрузка медиа.
- Административное PWA: установка после входа, «Позже» до следующего открытия админки, инструкция
  iOS, обновление. Приватные страницы, данные и API не кешируются.
- Title/Description, canonical, Open Graph, Schema.org, sitemap, robots.
- Сборка SCSS/JS, WebP, health endpoints, резервное копирование и очистка медиа.

## Перед реальной публикацией

Данные макета — демонстрационные: 12 товаров, 7 категорий, 3 точки и пример акции.
Цены по умолчанию скрыты. Адреса и графики точек нужно подтвердить. Координаты
специально не выдуманы — их вносит собственник. Добавьте остальные реальные точки.
Контакты из других проектов не перенесены.

В «Настройках» укажите телефон, email, реквизиты, оператора персональных данных,
утверждённые тексты политики и согласия. До заполнения документов приём заявок
отключён и на сайте, и на сервере. Это не ошибка установки.
В «Контенте» изменяются основные заголовки, подзаголовки, текст и hero-фотографии
главной, «О компании», «Партнёрам» и контактов. Повторяющиеся декоративные блоки
макета остаются в HTML; произвольного конструктора страниц нет.

Реальные домен, HTTPS, контакты, документы и проверку на ваших устройствах нельзя
подменить демонстрационными значениями. Индексация отключена до настройки домена.
Push, корзина, покупка, доставка, склад, кабинеты покупателей, сотрудники и
аналитика посещений отсутствуют согласно ТЗ.

## Проверки и сопровождение

```bat
npm run check
npm test
npm run security:audit
npm run backup
npm run media:cleanup
npm run media:cleanup -- --apply
npm run owner:reset
```

`npm test` создаёт отдельную `prisma/integration-test.db`, не трогая рабочую базу.
`media:cleanup` сначала показывает список; `--apply` удаляет только неиспользуемые
загруженные фото старше 24 часов. Ссылки на медиа проверяются по всем сущностям.
Смена пароля через `owner:reset` отзывает все сессии.

Результаты проверок и ограничения: [docs/PROGRESS.md](docs/PROGRESS.md).
Деплой и восстановление: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).
