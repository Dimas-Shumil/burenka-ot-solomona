В `public` нет ресурсов и админки. `admin-pages` находится рядом с `public`.
Express регистрирует EJS для расширения `.html`: пользовательская структура
сохранена, SSR не требует переименования страниц в `.ejs`.

## Поток запроса

Express → заголовки безопасности и request ID → разрешённая статика либо
JSON/form parser → cookies/CSRF → аутентификация → маршрут → Zod → сервис/Prisma
→ SQLite → SSR или JSON. Административные маршруты требуют активной OWNER-сессии.
HTML админки и приватные API получают `Cache-Control: no-store` и `noindex`.

Корень проекта, `public` и `admin-pages` напрямую не раздаются. Это предотвращает
обход авторизации через HTML и загрузку `.env`, базы, SCSS и серверного кода.

## Данные

User 1→N Session. Единственная допускаемая роль — OWNER.
Category 1→N Product; Producer 1→N Product, связь производителя необязательна.
Product 1→N ProductImage; Store 1→N StoreImage. Первая по `position` фотография
является обложкой. При удалении записи фотографии-связи удаляются каскадно.
Категорию с товарами удалить нельзя; удаление производителя обнуляет связь.

Promotion содержит период, изображение и ссылку; выдача проверяет начало и конец.
PartnershipRequest содержит поля обращения, статус, заметку, дату и версию согласия.
SiteContent — основные блоки четырёх страниц. SiteSettings — единая запись
контактов, реквизитов и документов. Media — только обработанные загрузки.

Индексы: опубликованность/категория/порядок, порядок фотографий, срок сессии,
статус/дата заявок. Slug уникален и после создания закреплён для постоянных URL.
Цены — целое число копеек, отображение независимо выключается. Фото хранятся
в файловой системе, в SQLite только пути и метаданные.

## Единый публичный каталог

Каталог, главная, поиск и рекомендации читают Prisma Product с условием
`published=true AND category.published=true`. Поиск нормализует NFKC, кириллицу,
регистр и ё/е, ищет по всем требуемым полям, включая категорию и производителя.
Поиск по небольшому B2B-каталогу выполняется в приложении, поскольку SQLite
по умолчанию не даёт корректный кириллический insensitive LIKE. При росте до
десятков тысяч товаров стоит перенести нормализованный поиск в индекс.

## Медиа

Вход: только OWNER + CSRF + максимум 8 МБ. Декодирование Sharp проверяет реальный
тип и лимит пикселей; SVG, GIF, анимации и подделки отвергаются. Изображение
поворот/resize до 1800px → WebP, без EXIF → случайный UUID → запись Media.
Публичные пути валидируются. Неиспользуемые загрузки удаляются отдельной задачей
с отсрочкой 24 часа, чтобы незавершённый редактор не потерял загруженные фото.

## Сессии и формы

Пароли scrypt N=32768/r=8/p=1 с индивидуальной солью. Случайный 256-битный
токен сессии хранится в cookie, в базе только SHA-256. Есть абсолютный и idle TTL,
отзыв при выходе и смене пароля, ограничение до пяти одновременных сессий.
Production использует Secure `__Host-` cookies, HttpOnly и SameSite=Lax.
CSRF — HMAC от отдельной HttpOnly cookie и проверка Origin; токен находится
в SSR meta и передаётся заголовком. Логин и заявки ограничены по частоте.
Реальная IP-модель nginx включается только `TRUST_PROXY=loopback`.

## PWA

Manifest и service worker только под `/admin/`. Приватное содержимое не
кешируется вообще; при offline-навигации — отдельный ответ «нет подключения».
Приложение не обещает офлайн-редактирование. Регистрация и установка доступны
после входа; публичные страницы и страница логина PWA не регистрируют.
Все переходы находятся внутри /admin/. Первичная активация SW не перезагружает
редактор. Версии CSS/JS и иконок включены в URL; номер сборки записан в
site/build-version.json. Обновление из другой вкладки также ожидает подтверждения.
Иконки any/maskable/Apple, обновление с проверкой несохранённого редактора,
«Позже» до следующего открытия админки, отдельная инструкция iOS. Push отсутствует.

## Карта и SEO

Leaflet поставляется локально с лицензией. OSM XYZ-тайлы загружаются браузером
по HTTPS; есть атрибуция и Referer, нет bulk/offline-prefetch. При росте нагрузки
замените MAP_TILE_URL на собственного провайдера согласно его условиям.
Источник условий: https://operations.osmfoundation.org/policies/tiles/
Координаты пользователя используются только в памяти браузера. Haversine даёт
прямое расстояние, а дорожный маршрут открывается во внешнем сервисе.

SSR, sitemap, canonical, OG, Organization/Product/GroceryStore/BreadcrumbList,
закрытие `/admin`, `/api`, `/search`. Domain/origin берутся из окружения, а не Host.
Индексация изначально выключена. Обещаний позиций в поисковиках/GEO нет.

## Зависимости и сборка

Prisma 6.19.3 выбран для SQLite и совместимости с существующим подходом.
Prisma CLI и client закреплены одной версией; `deepmerge-ts` переопределён до
8.0.2 из-за advisory. Sharp 0.35.5 включает исправления безопасности.
Реальные версии фиксирует package-lock.json. `npm ci` воспроизводит установку.
Sass собирает CSS, esbuild — JS, сборка копирует Leaflet и создаёт PWA-иконки.
Инструкция миграций v6: https://docs.prisma.io/docs/orm/v6/prisma-client/deployment/deploy-database-changes-with-prisma-migrate

## Постоянная оболочка админки

site/js/admin/navigation.js заменяет только #admin-main из авторизованного SSR,
сохраняя sidebar, topbar, PWA и нижнюю навигацию. initAdminPage создаёт отдельный
AbortController на каждый экран; dispose удаляет обработчики старой страницы.
История хранит только индекс и позицию прокрутки, без форм/заявок/HTML.
Несохранённый ввод остаётся только в DOM. Повторные переходы отменяют предыдущие
чтения, серверные права/CSRF проверяются как при обычной навигации.

Шрифты Inter/Manrope локальны, SVG-иконки задаются контролируемыми путями в
site/js/icons.js и используются сервером и браузером. Все новые ресурсы
участвуют в версии сборки. Меню используют native dialog и доступный фокус.
