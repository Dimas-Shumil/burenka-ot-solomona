## Установка патча: CMD

Остановите dev-сервер Ctrl+C. Сохраните свою .env, базу и uploads резервной копией.
Распакуйте патч в корень существующего проекта, заменив файлы. Затем:

```bat
cd /d C:\Users\ШУМ\WORKS\burenka-ot-solomona
npm ci
npx prisma generate
npx prisma migrate deploy
npm run build
npm test
npm run dev
```

Новых SQL-миграций нет. Не запускайте seed и создание OWNER повторно.
Обновите вкладку Ctrl+F5. В установленном приложении при предложении обновления
сначала сохраните форму, затем нажмите «Обновить».

## Что реально проверено

35 автоматических сценария: серверные функции, логин/email, формы, PWA,
конфигурация безопасности, полноэкранное меню и динамическая навигация.
Для навигации тесты работают с настоящим Express/SQLite и DOM: постоянство
оболочки, отмена несохранённой формы, повторное создание без дубликатов,
конкурирующие ответы, ошибка сети, история Назад. Сборка и синтаксис проверены.

Живая визуальная проверка в Chromium и физические устройства в этой среде
недоступны; DOM-тесты не доказывают пиксельную точность и отсутствие переполнения
на каждом размере экрана. Не выдаём это за измеренный браузерный QA.

## Порты и доступ

В среде выполнения проверены доступные TCP/UDP-привязки: обнаружены только
loopback TCP-сокеты. PID для них недоступны. Это не проверка компьютера отца,
боевого сервера, роутера или внешнего firewall.

При работающем сайте откройте второе окно CMD в папке проекта и выполните
`npm run security:check`: команда печатает HOST,
PORT, безопасные параметры сессии и список TCP/UDP-портов. Windows использует
netstat -ano. Пароли, SESSION_SECRET и DATABASE_URL не печатаются. Системные
порты автоматически не закрываются: они могут принадлежать другим приложениям.
На сервере приложение по умолчанию слушает 127.0.0.1:3108 за nginx. Внешние
80/443 и SSH проверяются отдельно на реальной машине.

## Ещё мелкие улучшения, которые стоит рассмотреть

1. Привести реальные фотографии продукции к единому масштабу и отступам внутри
   кадра. Это сделает каталог заметно ровнее даже без изменения карточек.
2. После реального наполнения проверить длинные названия на узком телефоне:
   где нужно, отредактировать переносы и краткие подписи без обрезания названий.
3. Единообразно оформить номера телефонов и графики всех точек, чтобы карточки
   читались одинаково. Значения при этом не выдумывать и не менять.

Это рекомендации по наполнению и финальной визуальной сверке, а не скрытое
расширение функций проекта. Все исходные числовые показатели сохранены.
